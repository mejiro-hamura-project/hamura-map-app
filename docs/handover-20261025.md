## 3. 現在の機能仕様

### 地図・イベント

佐々木さんのPR #6で、2026年版の会場地図、第1〜第4会場、ブース・店舗・エリア・ステージ演目、地図検索と詳細表示が統合されています。店舗・イベントのデータ正本は`app/src/mocks/`以下の実アプリ読み込み資産で、`docs/stores.json`は現在の全店舗データの正本ではありません。地図PNGの画面表示とQRの実際の設置位置など、現地情報・実機でしか確定しない点は別途確認します。

### スタンプラリー

注意事項→遊び方→参加登録→QR収集→合言葉→景品交換。全画面でホーム・イベント・スタンプラリー・投稿の4メニューを表示します。途中で他タブへ移動しても保存済みの進捗に復帰します。カメラ退出時はトラック停止。**登録・QR取得・解答・交換は端末内で完結**し、D1が不通でも先へ進めます。

- ラリー保存: `stampRally.v2`。旧`v1`のテスト登録は引き継ぎません。
- 画面上の参加者番号は**各端末内で採番され重複する**ため、D1の一意な識別子には使用しません。
- 物理QRはコース共通の`stamp-rally-position-1`〜`7`。QR読取テストは実施済みとの運営判断。会場に設置する位置・印刷物の最終確定は別作業。
- 景品交換の正式な現地管理は**紙またはGoogleフォーム等**。D1の交換日時は補助記録に限り、送信成功を景品交付の前提にしません。
- D1に個別のスタンプ取得履歴やニックネームは送りません。

### 口コミ

同一originの`/api/posts`でD1へ投稿・取得します。投稿本文は1〜500文字、写真・「いいね」は対象外。投稿先・ジャンルの絞り込み、ページ送り、保存失敗時の入力保持、重複送信防止を実装。**同じ匿名IDから60秒間に新規5件まで**です。会場Wi-Fiなどで同一IPになっても、別の匿名IDの投稿とは制限を共有しません。

匿名IDは`app.anonymousId.v1`でブラウザ内に保存するUUID v4です。口コミ・スタンプラリーのどちらから利用しても同じID。サーバーでは同じsecretでHMAC化し、`posts.author_hash`と`participants.participant_key`として保存します。ログインや本人認証ではなく、ブラウザデータ削除や別ブラウザでIDは変わり得ます。

不正投稿は通常`hidden`に変更して非表示にし、必要なら`visible`に戻す運用です。管理者専用Web UI、公開削除APIはありません。実際の操作例・CSV変換手順は[D1運用手順](anonymous-id-d1-operations.md)参照。

## 4. D1導入の現状と有効化

**2026-10-25の統合検証時点で実Cloudflare D1は未接続**です。実D1へmigrationは未適用、投稿受付・ラリー補助保存は停止中。`app/wrangler.jsonc`はDB bindingを含めず、`POSTS_ENABLED=false`、`RALLY_SYNC_ENABLED=false`が既定値です。

| 順序 | 担当・内容 |
| --- | --- |
| 1 | 大嶋先生のCloudflareアカウント、正式Worker、環境／URLと管理権限を決定 |
| 2 | 対象アカウントにD1作成、対象Workerへbinding名`DB`を設定（本番DB ID・secretはGitに書かない） |
| 3 | `0001_posts.sql`、`0002_participants.sql`を順に適用。実DB名・環境を確認し、初期テストデータを流し込まない |
| 4 | 長さ32文字以上の共通secret`POST_RATE_LIMIT_SECRET`を対象環境のsecretとして設定。キー変更は過去の匿名ID関連付けに影響する |
| 5 | 投稿・参加登録・交換・再送・非表示・CSVを対象D1で受入検証。運営者のアクセス制限、投稿の非表示担当、保存期限を決める |
| 6 | 試験が終わった環境のみ`POSTS_ENABLED=true`、`RALLY_SYNC_ENABLED=true`を有効化。まず別端末から読み書きを確認する |

詳細コマンドは[D1運用手順](anonymous-id-d1-operations.md)。登録情報には性別・年齢・学校区分が含まれるため、SQL/CSV/バックアップを公開しない。イベント終了後の削除時期は運営側で決める。運用開始後に匿名IDのHMAC secretを安易に変更しない。

**注意:** D1未接続中に送信失敗したラリーの最新snapshotは`stampRally.d1Sync.v1`に保存され、同じoriginで接続を有効にすると再送され得る。運用開始前にはテスト端末・テストデータを分離して確認すること。サーバー必達保証はない。

## 5. 動作確認と品質

`app/`を作業ディレクトリとし、Node.js 22.12以降で実行。

```sh
npm ci
npm run build
npm run lint
npm run test:identity
npm run test:stamprally
npm run check:worker
npm run test:posts:unit
npm run test:posts:integration
node --test scripts/data/export-csv.test.mjs
```

PR #8では共通ID・スタンプラリー状態・Worker単体・CSV・実ローカルD1・隔離Chromium・旧PWAからの更新試験がPASS。**実iPhone/Androidカメラ、実Cloudflare D1、正式公開環境の運用受入は未実施**であり、ローカルテスト成功と区別する。

- iPhone Safari / Android Chromeでフッター、狭い画面のスクロール、キーボード、カメラ権限・終了、端末進捗の保持と更新を確認する。
- PWAのキャッシュにより通常ブラウザで旧版が残ることがある。シークレットウィンドウまたはService Workerのネットワークバイパスで比較する。**安易にサイトデータ全消去を案内しない**（参加状態も消える）。
- リリース時にCloudflareの通常公開URLが最新デプロイか、`/api`がHTMLでなくJSONを返すか、フラグ・bindingが意図どおりか確認する。
- `npm ci`の依存監査警告（直近は9件）は未解消。期限を決めて別途調査し、無条件の`npm audit fix`で依存を一括更新しない。
