# お祭りスタンプラリー Webアプリ 開発プロンプト（AIコード生成用）

> 使い方：以下を丸ごと Cursor / Claude などに貼り付けてください。
> 必要に応じて「技術要件」や「配色」を自分の環境に合わせて書き換えてから使うと精度が上がります。

---

あなたは熟練のフロントエンドエンジニアです。市民祭り向けの「スタンプラリー機能」を、**スマホのブラウザで開くWebアプリ**として実装してください。以下の仕様を**忠実に**守ってください。

## 1. ゴール
来場者がお祭り会場に設置された **QRコードを7か所** 読み取り、1つずつ「文字」を集める。集めた文字で「合言葉」を完成させると景品と交換できる。全体はスマホ縦画面の1つのアプリとして動作する。

## 2. 技術要件
- **React + Vite + TypeScript** の SPA（シングルページアプリ）。
- レイアウトは **スマホ縦画面ファースト**。画面全体は `max-width: 420px` 程度で中央寄せし、スマホ実機・PC両方で崩れないようにする。
- スタイリングは **Tailwind CSS**（未導入なら CSS Modules でも可）。
- **QR読み取り**は `html5-qrcode`（または `@zxing/browser`）を使い、`getUserMedia` で背面カメラを起動する。カメラ権限が拒否された場合のフォールバック表示も入れる。
- 画面遷移は状態ベース（`useState`/`useReducer`）か `react-router` のどちらでもよいが、**モーダル（ポップアップ）とページ遷移を区別**する。
- **進捗の永続化**：収集済みスタンプ・登録情報・景品交換状態は `localStorage` に保存し、リロードしても復元されること。
- **バックエンドは不要**。QRコードの中身から文字を判定するロジックはクライアント側に持たせるが、後からAPI化しやすいよう、判定部分は関数に切り出しておく。

## 3. データ定義（※文字・言葉は仮。定数として一箇所にまとめ、後で差し替え可能にすること）
- 合言葉は **7文字**。仮の完成形：`はむらおしかつ`。
- 7つのチェックポイントを配列で定義する。各要素は「QRの値」「表示する文字」「合言葉内での並び順」を持つ。例：

```ts
// TODO: 実際のQR値・文字・言葉は運営確定後に差し替える（現在は仮）
const CHECKPOINTS = [
  { id: 1, qrValue: "STAMP_01", char: "か", phraseIndex: 5 },
  { id: 2, qrValue: "STAMP_02", char: "む", phraseIndex: 1 },
  { id: 3, qrValue: "STAMP_03", char: "し", phraseIndex: 4 },
  { id: 4, qrValue: "STAMP_04", char: "つ", phraseIndex: 6 },
  { id: 5, qrValue: "STAMP_05", char: "お", phraseIndex: 3 },
  { id: 6, qrValue: "STAMP_06", char: "は", phraseIndex: 0 },
  { id: 7, qrValue: "STAMP_07", char: "ら", phraseIndex: 2 },
];
// 合言葉表示は phraseIndex 順（= はむらおしかつ）に並べ替えて表示する
```

- **スタンプ収集グリッド**は CHECKPOINTS の並び（`id`順）で表示。
- **合言葉エリア**は `phraseIndex` 順に並べ替えて表示。
- この「グリッドの並び」と「合言葉の並びが違う」点も再現すること。

## 4. 画面仕様（添付UI案に忠実に。①〜⑨の順で実装）

すべての画面上部に共通ヘッダー「**お祭りスタンプラリー**」（2行・中央寄せ・太字）を置く。

### ① 注意事項
- **赤色の見出しバー**「注意事項」。
- 本文に「個人情報について」等の注意文（**文言は仮テキストでOK。差し替え前提**）。
- 画面下部に「**スタート**」ボタン（ダスティピンク）。押すと②へ。

### ② 遊び方の説明
- **緑色の見出しバー**「遊び方」。
- 番号付きの手順説明（QRを探す→カメラで撮る→文字を集める→合言葉を完成→景品交換、といった内容。**文言は仮でOK**）。
- 手順1〜4には画像を差し込めるスペースを用意しておく（今はプレースホルダー画像）。
- 画面下部に「**スタート**」ボタン。押すと③へ。

### ③ 参加者登録
- **黄色の見出しバー**「参加登録」。
- 入力項目：**ニックネーム**（テキスト・任意）／**性別**（プルダウン）／**年代**（プルダウン）。
- 画面下部に「**参加する**」ボタン。押すと入力を localStorage に保存し④へ。

### ④ スタンプラリー画面（メイン）
- 上部に「**現在のスタンプ数：0/7**」（収集数に応じて更新）。
- 中央に **7つの丸**のグリッド（3列想定）。未取得はグレーの丸、取得済みは**オレンジの枠線＋文字**の丸。
- その下に「**合言葉**」ラベルと、**7マスの枠**。取得した文字が `phraseIndex` 順に埋まっていく。
- 画面下部に「**カメラを起動する**」ボタン（紫・カメラアイコン付き）。押すと⑤へ。
- 7つすべて揃ったら、この画面上に**コンプリートのポップアップ**（後述）を表示。

### ⑤ カメラ画面
- **背景は黒の全画面**。
- 中央に**白枠の正方形**（スキャン領域ガイド）。
- 下部に案内文「**QRコードを写してください**」。
- 背面カメラを起動しリアルタイムでQRを読み取る。
- 閉じる/戻る手段を用意（④へ戻れる）。
- QRを読み取ったら判定：
  - 未取得のチェックポイント → 収集状態を更新し⑥（文字ゲット）を表示。
  - 取得済み → 「すでに取得済みです」等の軽い通知を出し、二重取得しない。
  - 未登録のQR → 「対象外のQRコードです」等のエラー通知。

### ⑥ スタンプゲット画面（ポップアップ）
- 「**文字ゲット！**」の見出し。
- 取得した文字を**大きくオレンジの丸**の中に表示（例：`は`）。
- 「**閉じる**」ボタン（オレンジ）。押すと④に戻り、グリッドと合言葉が更新されている。

### ⑦ 取得後の表示
- ⑥で取得した文字が④のグリッド（オレンジ丸）と合言葉エリアに反映される。
- 収集が進むほど文字が増えていく（例：`は` → `はむ` → … → `はむらおしかつ`）。

### ⑧ コンプリートのポップアップ（④の上に表示）
- 最後（7つ目）のQRを読み込んだ直後に表示。
- 「**コンプリート！おめでとう**」のメッセージ。
- 「**景品交換へ進む**」ボタン（ピンク/マゼンタ）。押すと⑨（景品交換画面）へ。

### ⑨ 景品交換画面
- 上部に完成した「**合言葉：はむらおしかつ**」を表示。
- 「**スタンプラリー コンプリート景品交換券**」のカード。
- 「**交換する**」ボタン（ブルー系）。押すと確認ポップアップを表示：
  - タイトル「スタンプラリー景品交換」、本文「**本当に引き換えますか？**」、ボタン「**OK**」「**キャンセル**」。
  - **OK** → 交換済み状態を localStorage に保存し、カードを「**交換済み**」（赤文字）表示に切り替える。ボタンは無効化し再交換不可。
  - **キャンセル** → ポップアップを閉じるだけ。
- 一度「交換済み」になったら、次回以降このアプリを開いても⑨は交換済み表示のままにする。

## 5. 画面遷移フローまとめ
① 注意事項 →(スタート)→ ② 遊び方 →(スタート)→ ③ 参加者登録 →(参加する)→ ④ メイン
④ →(カメラを起動する)→ ⑤ カメラ →(QR読取)→ ⑥ 文字ゲット →(閉じる)→ ④（更新）
④ で7/7達成 → ⑧ コンプリートポップ →(景品交換へ進む)→ ⑨ 景品交換 →(交換する→OK)→ 交換済み

## 6. 配色（UI案からの目安。厳密でなくてよいが雰囲気を合わせる）
- 注意事項バー：赤（例 `#E8524A`）
- 遊び方バー：緑（例 `#4CB37E`）
- 参加登録バー：淡い黄色（例 `#F7E9A0`）
- スタート/参加する：ダスティピンク（例 `#E39AA0`）
- カメラを起動する：紫（例 `#8B7ED8`）
- スタンプ取得済みの丸：オレンジ枠（例 `#F5A623`）
- 景品交換へ進む：マゼンタ寄りピンク（例 `#E060A8`）
- 交換する：ブルー系（例 `#A9B8E8` 背景に濃紺文字）
- 交換済み：赤文字（例 `#E8524A`）
- 背景：ごく薄いグレー、カードは白・角丸・軽いドロップシャドウ。

## 7. 状態管理（保持すべきデータ）
- `registration`: { nickname?, gender, ageGroup }
- `collectedIds`: number[]（取得済みチェックポイントIDの配列）
- `prizeExchanged`: boolean
- これらを `localStorage` に保存・復元。収集数・合言葉・コンプリート判定はここから算出する。

## 8. 実装上の注意・エッジケース
- 同じQRの二重取得を防ぐ。
- 未登録QR／読取失敗時のエラーハンドリングと通知。
- カメラ権限拒否時のメッセージ表示。
- リロード後も進捗・交換済み状態を維持。
- ボタンはタップしやすい大きさ（高さ44px以上）。
- 開発・テスト用に「QRを使わず手動で各スタンプを付与できるデバッグ用ボタン」を隠し機能として用意しておくと動作確認が楽（本番では非表示に）。

## 9. 未確定事項（仮のままでよい箇所）
- 注意事項・遊び方の**本文コピー**は未定。仮テキストで実装し、あとで差し替え可能に。
- **合言葉と文字数**は未定（現状「はむらおしかつ／7文字」は仮）。CHECKPOINTS を1か所書き換えれば全画面に反映されるようにすること。
- ニックネームは無し運用の可能性あり → **任意入力**にしておく。

## 10. 成果物
- 上記①〜⑨がひと通り動く、スマホWebアプリのソース一式。
- コンポーネントは画面ごとに分割し、定数（CHECKPOINTS・配色・コピー）を差し替えやすい形にまとめること。
- まず全体構成（ファイル構成・状態設計）を示してから、コードを実装してください。
